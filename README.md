# internet-speed-meter

[![CI](https://github.com/r-1805/internet-speed-meter/actions/workflows/ci.yml/badge.svg)](https://github.com/r-1805/internet-speed-meter/actions/workflows/ci.yml)

Скрипт для замера скорости интернета со своего компьютера. Принимает адрес тяжёлого файла
(например, большой картинки), **последовательно** выполняет 10 запросов, дожидается полного
ответа на каждый и печатает:

- среднее время запроса;
- объём скачанных данных;
- среднюю скорость в **Мбит/с** (и в МБ/с для удобства).

Только стандартная библиотека Python — ничего устанавливать не нужно.

## Требования

- Python **3.9+**

Проверить версию:

```bash
python --version
```

> На Windows вместо `python` может понадобиться `py`.

## Установка

```bash
git clone https://github.com/r-1805/internet-speed-meter.git
cd internet-speed-meter
```

## Запуск

```bash
python speedtest.py https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
```

Ещё адрес для проверки — тестовый файл Cloudflare на 25 МБ (кавычки нужны из-за `?`):

```bash
python speedtest.py "https://speed.cloudflare.com/__down?bytes=25000000"
```

### Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `url` | — | Адрес файла, обязательный. Только `http://` и `https://` |
| `-n`, `--requests` | `10` | Сколько запросов выполнить |
| `-t`, `--timeout` | `30` | Тайм-аут ожидания данных от сервера, секунды |
| `--json` | выкл. | Вывести результат в JSON (для скриптов и мониторинга) |

Справка: `python speedtest.py --help`.

### Коды выхода

| Код | Значение |
|---|---|
| `0` | Хотя бы один запрос успешен, статистика посчитана |
| `1` | Ни один запрос не выполнился |
| `2` | Неверные аргументы |
| `130` | Прервано через Ctrl+C |

## Как считаются метрики

- **Время запроса** — от начала запроса до получения последнего байта тела: DNS, TCP/TLS,
  ожидание ответа и скачивание. Время замеряется `time.perf_counter()` — монотонными часами,
  на которые не влияет перевод системного времени.
- **Время ответа** — через сколько пришли заголовки. Если оно большое, а скачивание быстрое —
  тормозит сервер, а не канал.
- **Объём** — реально прочитанные байты тела ответа (а не заявленный `Content-Length`).
- **Средняя скорость** = `сумма байтов / сумма времени` успешных запросов. Среднее
  арифметическое скоростей отдельных запросов не используется: оно завышает результат, если
  один запрос оказался случайно быстрым.
- **Мбит/с vs МБ/с.** Провайдеры и speedtest-сервисы указывают скорость в мегабитах, поэтому
  основная единица — Мбит/с. 1 МБ/с = 8 Мбит/с. Мегабайты десятичные: 1 МБ = 1 000 000 байт.
- Неудачные запросы в среднее не входят, но показываются в выводе и в счётчике
  «Успешных запросов».

## Ограничения

- Скрипт измеряет скорость **до конкретного сервера**, а не «скорость интернета вообще».
  Результат зависит от загрузки сервера, CDN и маршрута. Для честного замера берите большой
  файл (от 10 МБ) на быстром CDN.
- На маленьких файлах (сотни КБ) основное время уходит на установку соединения, и скорость
  получается заниженной.
- Скрипт отправляет `Cache-Control: no-cache`, но CDN может его игнорировать и отдавать файл
  из своего кэша — это обычно и есть нормальный сценарий работы.
- Каждый запрос открывает новое соединение, поэтому время включает TCP/TLS-рукопожатие.
  Первый запрос обычно медленнее остальных из-за DNS.
- Если сервер оборвал соединение раньше, чем отдал весь `Content-Length`, запрос считается
  ошибкой — иначе обрезанный ответ исказил бы статистику.

## Как использовался AI

Код написан вместе с Claude Code: я ставил задачу и план, AI писал реализацию, дальше всё
проверялось руками и тестами. Что поймали при проверке:

- **Обрезанный ответ считался успешным.** `http.client` при чтении кусками (`read(amt)`)
  молча возвращает пустой результат, если сервер закрыл соединение раньше времени, —
  `IncompleteRead` в этом случае не бросается. Первая версия засчитывала такой запрос как
  успешный и занижала скорость. Нашёл тест с «ломающимся» сервером, исправлено сверкой с
  `Content-Length`.
- **Ошибки `urllib` были нечитаемыми.** Настоящая причина (DNS, тайм-аут) лежит внутри
  `URLError.reason` — добавлена её распаковка в понятные сообщения.
- **Запрос без `User-Agent`** часть CDN (например, Wikimedia) отклоняет с 403 — добавлен
  собственный заголовок.
- Проверены сценарии: 404, несуществующий домен, закрытый порт, тайм-аут, неверные аргументы.
